# 规则统一治理 v5.2 — 全局 vs 项目双轨制合并

> **日期**：2026-09-02
> **基于**：Trae 官方文档 [docs.trae.cn/ide/rules](https://docs.trae.cn/ide/rules) + v5.1 智能生效化
> **目标**：消除「全局规则 vs 项目内规则」双轨制，统一指向全局 v5.2

---

## 一、背景

### 1.1 双轨制问题

**全局规则目录**：[`d:\filework\.trae\rules\`（78 文件 v5.2 场景化）](#)
**项目内规则目录**：[`excel-to-diagram/.trae/rules/`（52 文件 v4.0 扁平）](#)

**重叠问题**：
- 30+ 文件主题完全重复（如 SESSION_REMINDER、coding-standards、e2e-testing、powershell-execution-guide）
- 同样的 alwaysApply: true 出现两次（engineering-guidelines、multi-agent-coordination）
- 版本错位（全局 v5.1 vs 项目 v4.0）→ AI 困惑哪个权威

### 1.2 Trae 官方建议

> "**项目规则**是针对当前项目 AI 需要遵循的规则，仅在所配置的项目中生效。"
> "应用场景：代码风格、语言与框架、API 限定"

**本项目实践**：
- 详细规则放全局（跨项目通用）
- 项目内仅保留项目特定入口（如 AGENTS.md 核心铁律）
- 避免在项目内重复维护全局已有的规范

## 二、改造方案

### 2.1 方案设计：Stub 模式（最小破坏）

**原则**：
- ✅ 保留所有项目内文件名（避免破坏 git ref）
- ✅ 替换文件**内容**为跳转 stub
- ✅ 在 frontmatter 加 `[STUB 已废弃]` 前缀
- ✅ AI 看到 description 即知道不加载

**为什么不删除文件**：
- Git 历史保留可追溯
- 其他工具/脚本可能引用了这些路径
- 未来可选择性删除

### 2.2 Stub 模板

```yaml
---
alwaysApply: false
description: "[STUB 已废弃 2026-09-02] <原文件主题> 已迁移到 <全局路径>"
---
```

```markdown
# ⚠️ 本文件已废弃（2026-09-02 v5.2 治理）

> **已迁移至**：`<全局路径>`
>
> 本文件保留以避免破坏 git ref。请查阅全局权威版本。

---

# <原标题>（历史快照）
```

## 五、active/ 目录废除

### 5.1 历史背景

v2.1 治理机制（2026-06-21）建立 `active/` + `archive/` 模式：
- `active/` 唯一权威
- `archive/` 历史快照
- 根目录 = 向后兼容层

### 5.2 v5.2 取代

- 全局规则天然统一（不存在 active/archive 区分）
- 项目内不再保留副本
- 双目录模式被「单目录场景化」取代

### 5.3 唯一保留内容

[delta-deployment-safety.md](file:///d:/filework/.tae/rules/scenarios/2-deploy/delta-deployment-safety.md) **内容**已迁到全局，**机制**不再需要。
