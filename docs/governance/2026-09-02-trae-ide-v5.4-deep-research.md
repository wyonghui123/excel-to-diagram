## 二、关键发现（v5.4 独有，按重要性排序）

### 🔴 P1-1: Subagent 在 v5.4 重新定义（不是独立系统）

**v5.3 误判**：Subagent 是独立的 .md 文件系统

**v5.4 真相**（来自 `agent.md`）：
- Subagent = "可被其他智能体调用" 的自定义智能体
- 在创建智能体面板中勾选 "可被其他智能体调用"
- **必配 2 个字段**：
  - **英文标识名**（如 `project-analyzer`）：被调用时的唯一英文标识
  - **何时调用**（描述）：其他智能体调用该智能体的合适场景和时机
- **目前仅 SOLO Agent 可调用自定义智能体**

**对项目的影响**：
- v5.3 在 `.trae/agents/` 创建的 4 个 .md 文件实际是"伪 Subagent"
- Trae IDE 实际不一定会把它们识别为 Subagent
- 真实做法：在 IDE 中通过 UI 创建智能体并勾选 "可被其他智能体调用"

**修复方案**（待定）：先观察 Subagent 是否被实际调用，再决定是否迁移到 UI 创建

### 🔴 P1-2: SOLO Spec 模式生成 3 阶段文档

**官方定义**（来自 `solo-coder.md`）：

> Spec 模式面向更复杂的系统级任务。SOLO Agent 会根据你的需求生成完整的三阶段文档组，包括大纲（spec.md）、任务列表（tasks.md）和验收清单（checklist.md）。这些文档存储在项目根目录下的 `.trae/specs/` 目录中，按任务名称分组为独立文件夹。

**3 阶段文档**：
- `.trae/specs/<task>/spec.md` —— 大纲
- `.trae/specs/<task>/tasks.md` —— 任务列表
- `.trae/specs/<task>/checklist.md` —— 验收清单

**5 类适用场景**：
1. 从零搭建新系统/模块
2. 大规模重构（架构级 / 技术栈迁移）
3. 多人协作项目（Spec 文档作为 SSOT）
4. 高质量/高稳定性项目（核心业务/支付/安全）
5. 需长期维护的项目（项目知识资产）

**对项目的影响**：与 v5.0 spec/rfc Skill 重叠，可以直接替代：

### 🔴 P1-5: 沙箱 v2（`sandbox.json` + 网络控制）

**配置文件位置**：
- Windows: `%USERPROFILE%\.trae-cn\sandbox.json`
- macOS/Linux: `~/.trae-cn/sandbox.json`

**完整配置 schema**：
```json
{
  "filesystem": {
    "readWrite": ["绝对路径列表"],
    "readOnly": ["只读路径列表"]
  },
  "network": {
    "default": "allow",
    "allow": ["[10.0.0.0/8]", "*.github.com:443"],
    "deny": ["[192.168.0.0/16]"]
  }
}
```

**网络匹配规则**（仅 Windows）：
- `[ip]` / `[ip/mask]` / `[ipv6/mask]` —— 单 IP 或 CIDR
- `[ip]:port` / `[ip]:port,port` —— 单 IP 多端口
- `domain` / `domain:port` —— 域名
- `*.domain` / `*.domain:port` —— 通配符

**deny 优先级 > allow**

**白名单机制**：命令前缀白名单内的命令跳过沙箱（在 IDE 对话流设置中配置）

**高风险命令拦截**：rm -rf 等弹 3 选项卡（跳过 / 加白名单 / 本次运行）

**对项目的影响**：
- 项目已有 `d:\filework\.trae\rules\scenarios\2-deploy\delta-deployment-safety.md` v5.2
- 可选升级：用 `sandbox.json` 替代/补充沙箱白名单机制
- 网络控制（仅 Windows）可用于限制 AI 访问内网/外网

### 🟡 P2-1: Skill 新机制（`.agents/skills/` + skill-config.json）

**项目级 → 全局级升级**：在 IDE 中点"应用到全局"按钮

### 🟡 P2-3: Auto 模式 + Max 模式

| 模式 | 行为 |
|------|------|
