# 规则智能生效化 v5.1（基于 Trae IDE 官方文档）

> **日期**：2026-09-02
> **基于**：[Trae IDE 规则文档](https://docs.trae.cn/ide/rules) 深度学习
> **范围**：`d:\filework\.trae\rules\` 全部 78 文件
> **目标**：应用 Trae 官方「智能生效」机制，按需加载规则节省 Token

---

## 一、背景

### 1.1 Trae 官方 3 种生效方式

| 方式 | YAML 配置 | 行为 |
|---|---|---|
| **始终生效** | `alwaysApply: true` | 所有会话都加载 → 占 Token |
| **智能生效** | `alwaysApply: false` + `description` | AI 根据对话内容判断相关性 → 按需加载 |
| **指定文件生效** | `alwaysApply: false` + `globs` | 匹配 globs 文件时自动加载 |

### 1.2 本项目 v5.0 现状（改造前）

```
alwaysApply: true 的文件：13 个
├── 根目录入口：3（START_HERE / SESSION_REMINDER / IRON-RULES）
├── 场景 3 服务：1（service-management-v5）
├── 场景 5 开发：1（engineering-guidelines）
├── 场景 6 测试：2（debug-infrastructure-onboarding / test_rules）
├── 场景 7 多 agent：1（multi-agent-coordination）
├── 场景 8 元规则：3（powershell-execution-guide / powershell-curl-alias / trae-tips-from-forum）
└── .deprecated/：2（不应加载但仍设置 alwaysApply: true）
```

**问题**：
1. 8 条高频规则虽"alwaysApply"，但实际只在特定场景才需要 → Token 浪费
2. description 写得过于简单（"9 条铁律速查卡片 - 所有 Agent 必读"）→ AI 无法精准判断
3. 没有充分利用 Trae 官方的智能生效机制

## 二、改造方案（v5.1）

```
原则 1：普适 / 紧急 / 不可替代 → 保留 alwaysApply

原则 3：description 必须     → 包含「触发场景」+「关键词」+「后果」
```

### 2.4 description 写法规范

**好**（包含触发场景 + 关键词 + 后果）：
```yaml
description: "AI 在调试 API 报错、服务异常、SQL 报错时查阅此规则。强制使用 V2.2 调试工具链而非手动 taskkill。"
```

**差**（仅描述内容）：
```yaml
description: "调试基础设施 onboarding"  # AI 无法判断何时加载
```

## 三、Token 节省估算

### 3.1 改造前（每次会话加载）

| 类别 | 条数 | 平均行 | Token/条 | 总 Token |
|---|---|---|---|---|
| alwaysApply 8 条高频规则 | 8 | ~300 | ~2,500 | **~20,000** |

### 3.2 改造后

- **始终加载**（3 条）：~5,000 Token
- **按需加载**（8 条）：仅相关场景触发，平均 1-2 条命中 → ~2,500-5,000 Token

### 3.3 节省效果

```
节省 Token：~15,000-17,500 / 会话
节省比例：~75-87%（高频规则部分）
```

按当前项目每天 10+ 会话估算：**每天节省 ~150,000+ Token**。

## 五、潜在风险与缓解

| 风险 | 缓解措施 |
|---|---|
| AI 不识别 description 不触发加载 | description 写明"AI 在 X 场景时查阅此规则" |
| 紧急规则被忽略（如 debug-infrastructure）| 保留核心铁律 alwaysApply，description 加"强制"字样 |
| 多语言关键词漏匹配 | description 中英双语关键词（调试 / debug）|
