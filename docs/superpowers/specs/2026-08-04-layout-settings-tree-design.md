# 布局设置面板重构设计 — 树形大纲 + 行内参数（方案B）

> 日期：2026-08-04
> 状态：已确认方案B（设计 + 计划，本阶段不写代码）
> 所属模块：架构数据图表（AADiagramApp / RelationScopeTree 侧栏第 4 个 CollapsiblePanel「布局设置」）

## 1. 背景与问题

当前布局设置面板由 `LayoutControlPanel.vue` + `GroupItem.vue` 组成，采用**卡片式嵌套列表**：

- 每个分组一张卡片，用 `margin-left` 表达层级缩进。
- 卡片头部塞满控件：拖拽排序柄、方向切换（TB/LR）、可见边框 toggle、启用/禁用 toggle、添加子分组、删除按钮。
- 卡片内还有「已分配容器」列表、嵌套子分组卡片。

**痛点**：
1. 窄 sidebar（垂直滚动）下，卡片横向空间不足，控件密集、标签文字长，易拥挤。
2. 层级深时靠缩进堆叠，视觉上不可折叠，一屏只能看少量层级。
3. 参数（启用/可见/方向）与结构（容器/节点嵌套）混在同一卡片，职责不清。

## 2. 目标

- 结构清晰：用**可折叠树形大纲**表达容器/节点嵌套，替代卡片堆叠。
- 参数可用：启用/可见/方向等参数**行内**即可调整（方案B约定，不做独立属性面板）。
- 可编辑：支持新增/编辑/删除分组、拖拽移动元素。
- 适配窄 sidebar：垂直滚动下仍保持可用。

## 3. 约束

- 侧栏较窄（垂直滚动）。
- 不引入独立属性面板（区别于方案A）。
- 必须保持现有数据流不变：`chartConfig.layoutControl` 是唯一数据源，`Object.assign` 写回，EmbeddedChartView 通过 `layoutControlConfig` computed 消费。
- 不破坏现有分组数据模型与拖拽/移动/自动分组逻辑（`useLayoutControl.js`、`diagramConfigStore`、`groupModel`）。

## 4. 设计总览（方案B）

在一个窄栏内垂直排布：

```
┌───────────────────────────────────┐
│ [布局设置]  [+新增]  [🔍搜索]        │  ← 顶部工具条
├───────────────────────────────────┤
│ 树形大纲（可折叠）                    │
│  ▼ 领域A        [👁][⋯]            │  ← 行内高频图标(hover显)
│    ▼ 子领域A1   [👁][⋯]            │
│      ● 服务模块A1-1 [👁][⋯]        │
│      ● 服务模块A1-2 [👁][⋯]        │
│    ● 服务模块A2  [👁][⋯]           │
│  ── 未分配节点池 ──                  │
│    ● 服务模块C1   ● 服务模块C2       │
└───────────────────────────────────┘
```

- **统一视觉**：分组与节点统一为「树节点」，用缩进 + 箭头表达层级，用图标区分分组类型（领域/子领域/服务模块/业务对象）。
- **行内参数（混合）**：行内只保留最高频图标（启用/禁用、删除），其余参数收进「⋯」弹出的小面板（见 §6）。
- **折叠**：树节点可展开/收起，默认收起深层。

## 5. 结构（树形大纲）

### 5.1 数据承载
直接复用现有 `localConfig.groups` 递归结构（`groupModel`），无需新增数据模型：

```js
{
  id, type, title, parentId,
  children: [],        // 嵌套子分组
  containers: [],      // 已分配容器（节点）
  enabled, visible, direction,   // 行内参数
  groupType, sortOrder, layerSortOrder, isCenter, ...
}
```

### 5.2 渲染组件
采用**自定义递归树节点** `LayoutGroupNode.vue`（而非 `el-tree`）：

- **选型理由**：现有拖拽/移动/事件逻辑是手写的（`handleGroupDragStart` / `handleGroupDrop`），直接改造为递归树节点可完整复用，避免用 `el-tree` 重写拖拽与事件协议。
- 顶级：`LayoutControlPanel` 递归渲染 `groups`。
- 每个节点：`LayoutGroupNode`（递归嵌套 `children`）。
- 缩进由 `depth` 控制（每层 `16px`），配合展开箭头而非纯缩进。

### 5.3 节点类型图标
| 类型 | 图标 | 说明 |
|------|------|------|
| DOMAIN | 文件夹 | 领域 |
| SUB_DOMAIN | 子文件夹 | 子领域 |
| SERVICE_MODULE | 文件 | 服务模块（末端节点） |
| BUSINESS_OBJECT | 文件 | 业务对象（末端节点） |
| LAYOUT | 自定义 | 布局分组 |

### 5.4 折叠交互
- 有 `children` 或 `containers` 的节点显示展开箭头。
- 默认：深层折叠（如领域内子领域收起），避免一屏挤爆。
- 展开状态可用 `Map<id, boolean>` 本地维护，不写入业务数据。

## 6. 参数配置（混合：行内高频 + ⋯/右键弹出面板）

> 决策：不做独立 inspector（暂缓）。参数配置**全部在树的节点区域完成**，采用「行内高频 + 弹出面板」混合，解决窄栏拥挤。

### 6.1 行内保留（最高频，hover 显示）
| 参数 | 控件 | 说明 |
|------|------|------|
| 启用/禁用 | 眼睛图标（👁 划线=禁用） | `enabled`，禁用后子元素提升到父级 |
| 更多 | 「⋯」按钮 | 打开参数弹出面板（见 6.2），亦为右键入口 |

- 行内仅这 2 个图标，hover 才显示，hover 显示 el-tooltip。
- 行内预留「删除」图标：仅自定义分组显示（hover 可见）。

### 6.2 弹出面板（锚定节点，点击「⋯」或右键弹出）
一个小型 `el-popover`（`teleported` 锚定该树节点），承载**完整参数**：

| 参数 | 控件 | 说明 |
|------|------|------|
| 启用/禁用 | toggle | `enabled` |
| 显示边框 | toggle | `visible` |
| 方向 | 两个小图标按钮 TB/LR | `direction`，仅分组且有多子节点时显示 |
| 颜色 | 色板/select | `color` |
| 排序 | 上移/下移 按钮 | `sortOrder` / `layerSortOrder` |
| 添加子分组 | 按钮 | 仅分组 |
| 删除 | 按钮（危险色） | 仅自定义分组 |

- **双入口**：点击「⋯」按钮 + 右键节点，均弹出同一面板，兼顾可发现与效率。
- popover 不随行宽限制，可容纳更多参数，从根上解决窄栏拥挤。

**窄 sidebar 专项**：
- 行内控件**只用图标**，不用文字标签。
- 行内图标 hover 才显示（避免每行常驻拥挤）。
- 行高控制在 28px 内，保证竖排容纳更多层级。

## 7. 可编辑 / 新增 / 拖拽

### 7.1 新增
- 顶部工具条「+ 新增分组」：在当前选中节点下新增子分组（无选中则加到顶层）。
- 弹出面板内「添加子分组」按钮：仅分组可用。
- 新增走现有 `createGroup` / `handleAddChild` 逻辑。

### 7.2 编辑
- 双击节点标题进入内联编辑（复用现有 `startEditTitle` / `finishEditTitle` 逻辑）。

### 7.3 删除
- 弹出面板内「删除」按钮（危险色）：仅自定义分组可删（复用 `handleDelete`）。

### 7.4 拖拽移动
- **树内拖拽**：拖拽节点重排、跨层级移动（复用现有 `handleGroupDragStart` / `handleGroupDrop` 逻辑，作用于 `children` 数组）。
- **容器分配**：从「未分配节点池」拖入某分组行 = 分配；从分组行拖回池 = 移除。
- 拖拽时显示目标高亮 + 落点提示（插入/成为子节点）。

## 8. 窄 sidebar 专项优化

1. **折叠默认收起**：深层结构默认收起，需要时展开。
2. **图标化控件**：行内仅图标 + hover tooltip，无文字标签。
3. **虚拟滚动**：容器数量大（数百个）时，树形列表启用虚拟滚动（`el-virtual-scroll`），保证流畅。
4. **紧凑行高**：行高 ≤ 28px。
5. **搜索**：顶部搜索框按 `title` 过滤节点（高亮匹配），快速定位。

## 9. 组件结构（改造后）

```
LayoutControlPanel.vue          // 保留：标题、工具条、未分配池、递归渲染树
└── LayoutGroupNode.vue         // 替代 GroupItem：树节点行（递归）
    ├── 展开箭头 + 类型图标 + 标题(内联编辑)
    ├── 行内参数区（启用/可见/方向/加子/删除，hover 显示）
    └── 递归 children
```

- `LayoutGroupNode` 复用 `GroupItem` 现有的事件协议（`update` / `delete` / `add-child` / `assign-container` / `remove-container` / `reorder-groups`），保持 `LayoutControlPanel` 的 `handleGroupUpdate` 等处理逻辑不变。
- 数据写入仍走 `Object.assign` → `chartConfig.layoutControl`，渲染链路不变。

## 10. 迁移与风险

| 项 | 说明 |
|----|------|
| 数据模型 | 不变，复用 `localConfig.groups` 递归结构 |
| 事件协议 | 复用 `GroupItem` 现有事件，避免改 `LayoutControlPanel` 业务逻辑 |
| 拖拽/自动分组 | 复用 `useLayoutControl` / `diagramConfigStore` 现有函数 |
| 风险：样式回归 | 逐项对照现有卡片样式，迁移到树节点样式 |
| 风险：深层嵌套渲染 | 用递归 + 折叠控制，避免一屏渲染过多 |

## 11. 测试

- 单元测试：树节点渲染 / 折叠 / 行内参数变更 emit / 拖拽重排与跨层级移动 / 新增/删除。
- 组件测试：`LayoutGroupNode` 渲染不同 `groupType` 图标、`enabled`/`visible` 状态。
- 回归：现有 `useLayoutControl.spec.js`、`diagramConfigStore` 相关测试保持通过。
- 手工验证：窄栏下折叠/展开、拖拽、参数变更后图表实时反映（方向/引擎/分组 disable 能力）。

## 12. 非目标（YAGNI）

- 不做独立属性面板（方案A）。
- 不做多选批量操作。
- 不改变布局引擎/方向/分组数据流（属于图表能力，已在前序任务验证）。
