## 2. 根本原因

### 2.1 V007.86c 计划任务设计 (有弹窗)

```
要运行: alert_monitor_v0760.bat
```

**`alert_monitor_v0760.bat` 内部**:
```bat
@echo off
setlocal
...
"%PYTHONW%" "%SCRIPT%" --config ... --check-now
```

**问题**:
- .bat 由 cmd.exe 解释执行
- 即使内部用 pythonw.exe (无 console)
- **cmd.exe 自身会弹一个黑色窗口 (虽然一闪而过)**
- 每 5 分钟一次, **用户被打扰**

### 2.2 V007.86e 修复 (无弹窗)

```
要运行: C:\Users\...\pythonw.exe "alert_monitor_v0760.py" --config ... --check-now
```

**优势**:
- 计划任务**直接**调 pythonw.exe
- pythonw.exe 是无 console 的 Python
- **0 个 cmd 窗口弹**
- 用户不被干扰

**Arguments**:
```
"D:\filework\worktrees\release-prep\tools\alert_monitor_v0760.py" --config "..." --log-file "..." --check-now
```

**V007.86b v2 的 bug** 是缺 `--check-now`. 这次 V6 XML **加**了 `--check-now`, 走 `main()` 的 `if args.check_now` 分支, 跑 `run_once_v0760(...)`, **exit 0**.

## 5. V007.86e 教训 (V007.86f+ 加 AGENT_INFRA §0.8)

### 5.1 教训 1: 计划任务直接调 pythonw.exe, 不要用 .bat wrapper

**理由**:
- .bat 弹 cmd 窗口
- 干扰用户工作
- .bat 编码问题 (V007.86c 教训)
- 调试更复杂 (多一层)

**例外**:
- .bat 内部需要复杂逻辑 (e.g. 环境变量, 多个命令)
- 这种情况用 V007.86e 改的 bat (PowerShell Start-Process Hidden)

### 5.2 教训 2: 计划任务的 Command 跟 Arguments 拆分

**V007.86b v2 bug**: 把所有参数塞到 Command 里, 缺 --check-now
**V007.86e 修复**: Command = pythonw.exe, Arguments = 完整参数列表

**未来**: 写 XML 用 V007.86d `generate_scheduled_task_xml.py` (避免手工拼 XML).

### 5.3 教训 3: 弹窗问题不只 .bat, 还有 PowerShell + Start-Process

**V007.86e 备用方案**: `powershell -NoProfile -Command "Start-Process ... -WindowStyle Hidden"`
- 这个组合在 .bat 内可用, 隐藏启动的 python 窗口
- 但 .bat 自身弹窗还是要解决 (V007.86e 主方案: 不要 .bat)

### 5.4 教训 4: 计划任务跑后必须 verify "上次结果"

**V007.86c** 上次结果 0 验证成功
**V007.86e** 上次结果 0 验证成功 + 验证无 cmd 弹窗 (用户报告)
