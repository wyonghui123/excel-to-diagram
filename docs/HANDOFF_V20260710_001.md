## 三、数据库迁移（部署后必须执行）

### 3.1 BUG-V049: version 唯一索引迁移

```bash
python meta/migrations/fix_version_unique_index.py
```

- 删除旧索引 `uidx_versions_name` (name 单字段全局唯一)
- 创建新索引 `uidx_versions_product_name` (product_id, name 联合唯一)
- **幂等**: 重复执行不会报错

### 3.2 BUG-V053: relationship 索引变更

**注意: 此迁移没有独立脚本, 由 YAML + index_rule_engine 自动处理**

- 旧索引 `uidx_relationships_version_source_target_type` (version_id, source_bo_id, target_bo_id, relation_code) UNIQUE → 删除
- 旧索引 `uidx_relationships_version_source_target_direction` (version_id, source_bo_id, target_bo_id, relation_direction) UNIQUE → 删除
- 新索引 `idx_relationships_version_source_target_type_dir` (version_id, source_bo_id, target_bo_id, relation_type, relation_direction) COMPOSITE (非唯一)
- 新索引 `uidx_relationships_version_code` (version_id, code) UNIQUE (应用层校验)

**建议**: 部署前手动执行 SQL 确认索引状态:

```sql
-- 检查现有索引
SELECT name, sql FROM sqlite_master WHERE type='index' AND tbl_name='relationships';

-- 如果旧唯一索引存在, 需要删除并重建:
DROP INDEX IF EXISTS uidx_relationships_version_source_target_type;
DROP INDEX IF EXISTS uidx_relationships_version_source_target_direction;
CREATE INDEX IF NOT EXISTS idx_relationships_version_source_target_type_dir ON relationships(version_id, source_bo_id, target_bo_id, relation_type, relation_direction);
-- uidx_relationships_version_code 由应用层校验, 不加 DB unique constraint
```

### 3.3 BUG-V052: 审计日志权限 code 重命名

**需执行 init_menu_permissions.py 更新权限数据:**

```bash
python meta/scripts/init_menu_permissions.py
```

**DB 层面需手动执行 (如果已存在旧权限 code):**

```sql
-- 重命名权限 code (消除双重前缀)
UPDATE role_permissions SET permission_code = 'audit_log:list' WHERE permission_code = 'audit_log:audit_log_list';
UPDATE role_permissions SET permission_code = 'audit_log:read' WHERE permission_code = 'audit_log:audit_log_read';
UPDATE role_permissions SET permission_code = 'audit_log:delete' WHERE permission_code = 'audit_log:audit_log_delete';

-- 清理无法映射的旧权限记录
DELETE FROM role_permissions WHERE permission_code LIKE 'audit_log:audit_log_%';
```

## 五、风险评估

### 5.1 高风险项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| relationship 索引变更 (唯一→复合) | 历史脏数据可能违反新约束 | 先 SELECT 查重, 确认无冲突再 DDL |
| 审计日志权限 code 重命名 | 旧 code 不再被识别, 已授权用户可能失去权限 | 迁移 SQL 必须执行; 建议先备份 role_permissions 表 |
| schema_loader 大幅扩展 | 前端可能收到之前没见过的字段 | 纯新增字段, 不删不改变有名, 向后兼容 |
| chain_owner_resolver 移除 is_in_chain | 权限范围可能扩大 | 新增的 SM/BO/relationship 追溯都是正确的 owner 路径 |

### 5.2 回退方案

- 部署前备份 `architecture.db`
- 保留上一个 deploy zip
- smart_deploy.sh 支持自动回退
