## 6. 给未来 Agent 的 4 条铁律

### 6.1 看到 N 个 dirty 不要慌

```
> [WARN] 工作区有 1388 个未提交修改
```

这个数字**包括**:
- 已 tracked + 已 modified (M)
- 已 tracked + 已 deleted (D)
- Untracked (??)
- Staged (A, M, D)

**真实数** (用 `git status --porcelain`) 通常**比这个数字小 1.5-2x**.

### 6.2 先 catagorize 再决定动不动

1. **D 是不是真删?** (e.g., `git log --diff-filter=D --name-only HEAD~5..HEAD` 看是不是 HEAD commit 删的)
2. **M 改了什么?** (e.g., `git diff --shortstat` 看 +/- 净行)
3. **?? 是什么?** (e.g., `ls -la <path>` 看是不是 .gitignore 漏的)

**原则**: 除非你能 100% 确认是自己引起的, 否则**不动** working tree.

### 6.3 别的 agent 的工作不要清理

PM 部署智能体 / 协调智能体 / dev agent / doc agent 都在**不同 worktree** 工作.
**他们 commit pending 时**, 他们的 working tree **也是 pending**.
如果你**清理**他们的 worktree dirty:
- 你会**删除**他们的 untracked (丢了他们的工作)
- 你会**revert** 他们的 modified (覆盖了他们的代码)
- 你会**bring back** 他们的 deleted (破坏他们的清理)

**结果**: 他们的 commit 时, 你的"清理"**全部回滚**, 而且他们会**不知道**为什么有些文件"复活"了.
